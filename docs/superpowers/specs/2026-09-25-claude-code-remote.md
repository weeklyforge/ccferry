## 背景与目标

不在电脑旁时：**监控进行中的 Claude Code 开发进度、续聊会话、远程批权限、收完成/阻塞推送，以及管理个人知识库**——尽量复刻本地操作体验。知识库管理（2026-09-26）升级为一期核心：浏览/搜索/阅读 + 编辑/新建 + 指挥 agent 整理。

需求原话五条：① 电脑有 Obsidian 类 md 笔记作知识库；② 电脑装 Claude Code 管理知识库；③ 电脑上多个开发项目用 CC 开发；④ 离开电脑后无法监控进行中项目进度、无法看知识库；⑤ 开发一套系统远程与电脑上的 CC 交互，复刻本地体验（对话历史/历史会话管理），含 APP 远程监控与操作。

## 架构基石（本机实证）

- **CC 会话 = `~/.claude/projects/<项目>/<session-id>.jsonl` 本地文件**（按项目分目录，单会话可达数十 MB 且实时写入）；本地 TUI 只是视图之一
- 系统本质 = **给同一份会话数据长第二个视图**
- **双平面**：监控面只读（fs watch 会话文件实时流出，本地在跑的任务也能看，零干扰）+ 操作面读写（Agent SDK `resume` 空闲会话接完整历史 / 开新会话）
- **红线：同会话不双写**——TUI 活跃时远端只读；续聊前按活动窗口判空闲

## 架构总览（v4）

```
手机/浏览器 ──HTTPS 443──▶ 云服务器（39.105.92.24）
                            ├─ /        → 静态 PWA（云端直出，不过隧道）
                            ├─ /api,/ws → 隧道服务器（自研私有协议）⟵ WSS ⟵ PC agent 客户端
                            │            （Agent SDK + 会话 watcher + 知识库服务 + localhost API）
                            └─ Web Push ← PC→云 event 流
```

- **宿主拍板**：脑 = 电脑（项目+会话文件+vault 都在这，云端当不了脑）；云 = 门
- **云机拍板（09-26）**：`39.105.92.24` = 智控-轻量2（阿里云，热力智控现有机器，兼用）——与智控业务同机：端口错开、资源隔离；京能云为私有云无法直连公网，从来不是门的候选
- **语言拍板**：全 TS 单语言（monorepo，协议帧类型共享）
- **打包拍板（09-26）**：客户端与服务端均**单包**——每端一个进程、一个制品、一条命令起：PC 端 = SDK+watcher+知识库服务+localhost API+隧道客户端同进程；云端 = 静态直出+隧道服务+Web Push 同进程
- **定名（09-26）**：ccferry——摆渡会话流（ccdeck/ccgate 均已被 CC 生态项目占用，查重后选定）

## 组件规格

### 1. PC agent 客户端（daemon）

- Claude Agent SDK（TypeScript）：`query()` + `resume` + `sessionStore`；GLM 端点走现有环境变量（实施首验）
- `canUseTool` 回调 = 权限闸：PWA 在线 → 推批准 UI（允许/拒绝/60s 超时即拒）；无人值守 → 预授权白名单外一律拒+留言（M1 先以 deny-all 落地）
- 会话 watcher：监听 `~/.claude/projects/**` 增量行解析 → 实时流；项目目录 munged 名仅作展示兜底，权威项目路径取自会话行内 `cwd` 字段
- localhost HTTP+SSE API（会话列表/流/续聊/历史/vault 服务）

### 2. 私有隧道协议 v0（自研，借鉴 FRP 子集）

- 传输：单条 **WSS 出站长连接**（PC→云，443 与网页共口共证书）
- 帧（二进制、长度前缀）：`AUTH/AUTH_OK`（首帧 token 验证）· `OPEN{streamId,kind: http|ws|event}` · `DATA` · `CLOSE` · `PING/PONG`
- 流映射：手机 `/api/*` → 云 OPEN → PC → localhost API → 回灌；`/ws` 长流直通；PC→云 `event` 常驻流（推送源）
- 断线：指数退避重连；每流窗口（防慢请求堵全连接）
- **抄 FRP**：多路复用+每流窗口、token 认证、流路由；**不抄**：配置系统/STCP/P2P/visitor/仪表盘

### 3. 云服务器

- 静态 PWA 直出 + 隧道服务端 + Web Push（VAPID，event 流驱动）
- 认证：手机侧单用户长期 token（签发 JWT）；PC 侧隧道 token；云端被打穿仍有两层 token 门槛

### 4. PWA 客户端（一期，原生二期）

- Vue + 移动优先；加主屏全屏；Web Push（iOS 16.4+ 需加主屏后授权）
- 页面：会话总览（项目×会话矩阵）· 会话实时流 · 续聊输入+权限批准卡 · 历史（搜 JSONL）· **知识库管理**（目录树/全文搜索/笔记编辑器/agent 指令入口——一期核心）· 设置

### 5. 知识库服务（daemon 内，M2，一期核心）

- vault 路径可配置；API：目录树 / 读笔记 / 写·新建笔记 / 全文搜索（底层 ripgrep）
- **安全沙箱**：全部文件操作锁死在 vault 根内，路径穿越一律拒绝；写入依赖 vault 既有 obsidian-git 自动提交兜底，daemon 不自建版本链
- 「agent 整理」= 创建/续接 cwd 为 vault 的 CC 会话并发指令（复用操作面，无新机制）

## 风险与待验证

- R1 会话 JSONL 无正式格式契约，CC 升级可能改格式 → 解析层隔离+容错（解析失败降级为原始行透传）
- R2 同会话并发写行为未定义 → 红线机制 + M1 查明 resume fork 语义
- R3 iOS PWA 推送限制（须加主屏）→ 一期接受，原生二期根治
- R4 云端被打穿 = 会话内容可见（隧道非 E2E）→ 二期可选 app 层端到端加密
- 已验证（09-24 spike）：CLI 无头事件流可解析 + `--resume` 跨进程接续（GLM 端点；`unrecognized_model` 警告无害）
- SDK 侧三项首验在 M1 计划 Tasks 2-4（GLM 继承 / 跨存储 resume / fork 语义），证据落 `docs/notes/m1-findings.md`
